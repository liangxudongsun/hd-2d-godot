# 雪山远景：原画、几何法线与构图

## 原画与加工边界

`source/snow-master.png` 是用户选定、去除近景并归约细节后的 ImageGen 原画。
运行用 `assets/forest-hamlet/backdrop/color.png` 通过字节复制生成，既不重采样，也不改颜色；源与目标 SHA-256 必须相同。

| 项目 | 记录 |
|---|---|
| 原生尺寸 | 1983 × 793 |
| 源 SHA-256 | `fa11b07fc545379570c1a86f8f5c70a5d5fe01c38aa4ffd2306ad6c5d381ce8c` |
| 图像来源 | 用户选定、去除近景并归约高频细节后的 ImageGen 雪山原画 |
| 颜色身份要求 | 源文件与运行颜色 PNG 必须 byte-identical |

取样、画面裁切、方向性明暗和昼夜色调由运行材质处理，不覆盖原画文件。原始生成器的模型版本和随机种子不可从 PNG 恢复，因此不得补写假定值。

`normal-rig.json` 在原画的归一化 UV 中标注 10 个远山体、20 个大雪面。每个面的切线法线是明确的方向向量；法线数据由这些几何标注生成，不使用 RGB 亮度推断高度。5 像素边缘过渡仅作用技术掩模。下方雾带逐渐回到平法线，天空与最下方雾层固定为 `(128,128,255)`。

`tools/forest_hamlet/prepare_snow_backdrop.py` 可重复生成 `normal.png`、`regions.png` 和带校验的 `manifest.json`。`regions.png` 的 R 是山面置信度、G 是可选的语义距离元数据、B 是下部薄雾权重；G 不是实测深度，也未用于切割颜色层。

rig 的每个山体记录峰点、两侧边界、脊线底点、左右面的法线与权重。切线约定为 X 向右、Y 向上、正 Z 朝向观察者。生成器检查原画身份、尺寸对齐、天空和底部平法线、向量单位长度误差、左右雪面方向与非亮度高程来源；实际材质响应仍须用 GPU 对照验证。

## 运行表现

`scripts/forest_hamlet/snow_backdrop.gd` 创建一块距相机视深 135 米的背景板，沿相机 Y/Z 跟随，并在 X 方向保留 0.35 倍相对位移。关闭视差后完全随相机移动，雪峰的屏幕坐标保持稳定。它不修改相机角度、FOV、角色缩放或行走逻辑。

板保持原画比例映射，并将主峰中心放在画面横向 50.5%、纵向 -1.5% 处（峰尖轻微裁顶），使雪面进入既有树冠之间的中央开阔区域。真实物理板覆盖整个视口，超出原画底边的取样钳位到原画已有的平静雾带；正常游戏中该区域被地面遮挡。这是完整单板的视差，不宣称已经生成天空、山体等独立颜色层。

首次 GPU 预览中，主峰落在右侧红叶树冠后，只露出一个小角。因此修订背景板内的原画横向位置，并把映射的最小宽度从 230 米改为 **255 米**，为构图偏移和正常横移保留原图余量。这个变更保持源图宽高比，不移动相机、角色、树木或建筑。

以下是 1920 × 1080、39° FOV、基准相机 X=0 的布局计算，不代替最终截图：

| 相机 X | 主峰屏幕 X | 可见原图 U 范围 |
|---:|---:|---:|
| −14 | 1024.95 px | 0.264–0.931 |
| 0 | 969.60 px | 0.283–0.950 |
| +14 | 914.25 px | 0.303–0.969 |

最高峰尖有意在画面上方，`main_peak.in_frame=false` 可以是正确构图。实际像素匹配优先使用 `main_snow_ridge`（UV `[0.629,0.330]`）和 `left_shoulder`（UV `[0.586,0.365]`）。运行快照记录地标的 UV、世界位置、真实投影，以及板四角与覆盖余量。

当前只有 **1 个完整颜色背景板**。角色正常行走带来的镜头横移驱动村庄与整块远景之间的相对位移；背景自身没有替代行走的漂移动画。天空、远山、主雪峰和雾带画在同一张原画中，彼此不会独立错移。若后续需要多层视差，应补齐被遮挡的图像区域并另存独立图层，不能把原图切成横条后直接错移。

`shaders/forest_hamlet/snow_backdrop.gdshader` 根据实际主光的世界方向转换到板局部空间，计算法线和光线的点积。以平面法线的响应为参照，在原画上增加克制的方向性明暗；天空与下部雾不参与凹凸照明。正常颜色、法线开关、左右光方向可做同条件 GPU A/B。由于原画已有绘制光照，该方法是风格化动态重光照，不是从真实无光照反照率恢复的物理山体。

日光与黄昏切换会刷新主光方向、光色和预设亮度；关闭雪山法线会撤去山面的方向性响应。材质使用显式动态重光照，`unshaded` 标志用于绕过 Godot 再次施加整套 PBR 照明。验收须使用实际材质、对称左右白光和法线 ON/OFF 四张 GPU 图像，确认山面像素确实随方向变化，天空和雾层不出现凹凸光斑。

原画已有淡金色受光与蓝紫阴影，主光改变不能完全消除这些已经绘制的照明，也不会产生新的山体几何投影阴影。过强的法线或与原画完全相反的主光可能增加不自然感，因此默认保持温和响应。村庄上空的云影由独立的 `cloud_lighting.gd` 参与原生阳光阴影；远景板自身不投影，也不把这片局部云的阴影叠到遥远雪山上。WorldEnvironment Glow 和体积雾独立控制。

## 场景接入接口

- `configure(camera, sun)`：创建材质与背景板。
- `update_frame()`：按相机与主光当前值刷新，即使场景已冻结仍可显式调用。
- `tick(delta)`：累加诊断时间并刷新；背景本身没有独立漂移动画。
- `set_normals(enabled)`、`set_parallax(enabled)`、`set_preset("day"|"dusk")`：分项控制。
- `landmark_world(uv)`：原画 UV 到实际世界坐标。
- `snapshot()`：来源、单板声明、法线方式、光方向、覆盖余量，以及所有地标的真实投影坐标。

原画多层拆分尚未实施；此限制必须随运行证据明确保留。真实 GPU 截图、左右行走和光照 A/B 由场景验收流程负责。
